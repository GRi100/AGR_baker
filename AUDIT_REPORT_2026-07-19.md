# AGR Tools — аудит кодовой базы и план развития

**Дата:** 19.07.2026
**Метод:** многоагентный аудит (31 агент): 5 глубоких читателей модулей → 22 адверсариальных проверяющих (каждая заявленная проблема перепроверена по живому коду рабочей копии, одна — эмпирически в headless Blender 5.0.1) → 3 идеатора с разными ракурсами.
**Итог:** 5 подтверждённых критичных багов, ~11 средних, 5 заявленных проблем опровергнуто, 28 идей улучшений.

## 1. Почему «отключена» кнопка Create Atlas

Два разных механизма, оба — логика UI, а не баг, но непрозрачная для пользователя:

- **Create Atlas from Object** (`ui.py:295-308`) рисуется серой (`row.enabled = False`), когда активный объект — не MESH или у него нет ни одного слота материала. Причина нигде не показывается.
- **Create Atlas Only** (`ui.py:331-347`) **полностью исчезает**, если ни один текстурный сет не отмечен галочкой в списке (нужен хотя бы один `is_selected` и не-атлас). Вместо кнопки — label «Select texture sets to create atlas». Обе секции («Atlas Operations» и «Atlas from Selected Sets») свёрнуты по умолчанию. У оператора `AGR_OT_CreateAtlasOnly` нет `poll()` — из F3 он запускается всегда, пустой выбор отсекается только в `execute`.

**Чтобы увидеть кнопку:** раскрыть Atlas Operations → Atlas from Selected Sets и отметить галочками сеты в списке.

### Незакоммиченный блок — фактически релиз 2.1.0 (+1742/−293 строки)

- **Ребрендинг** `AGR_baker_v2` → `AGR_tools` (внутренние ID `agr_baker_settings` и пр. сохранены для совместимости с .blend).
- **Три новых модуля:** AGR Lights (замена объектов светом), AGR Sync (Outliner→3D View через msgbus), пасхалка Кати (подтверждение Separate → By Loose Parts).
- **Мультиатлас:** `agr.create_multi_atlas_from_object` — FFD-упаковка по нескольким бинам, per-bin нейминг `A_addr_Type_i`, мультиматериальный UV-ремап.
- **UDIM:** `agr.convert_tile_to_set` — извлечение одного тайла в сет без разборки UDIM.
- **Mirror:** зеркалирование сетов в `S_*_mirrorX/_mirrorY` с инверсией каналов нормалей.
- **Фиксы:** реконнект текстур в rename (короткие коды), безопасный cleanup (удаляет только созданные файлы), numpy-оптимизации бейка, фикс удаления дубликатов образов.

> ⚠️ **Важно про git:** фикс потери текстур при rename существует **только в рабочей копии** — закоммиченный HEAD всё ещё содержит баг. `git checkout .` уничтожит фикс. Коммитить в ближайшее время, разбив на логичные коммиты (ребрендинг / новые модули / мультиатлас / фиксы).

## 3. Подтверждённые баги

### 3.1 Критичные (потеря данных или тихая порча)

| # | Где | Суть |
|---|---|---|
| 1 | `operators_rename.py:699` | **Тип `do` распознаётся, но не переподключается.** Переименованный DO-файл не грузится → старый image-датаблок удаляется → cleanup стирает новый файл с диска. DiffuseOpacity теряется и в материале, и на диске. Единственная реальная незавершённость текущего диффа. В `operators_rename_project.py` бага нет (там reconnect грузит все типы). |
| 2 | `operators_atlas.py:1892` | **Упакованный `T_*_ERM.png` никогда не читается при сборке атласа.** Для HIGH-сетов (DO+ERM+Normal) каналы E/R/M заполняются дефолтами (E=0, R=0.5, M=0) — эмиссия и металличность молча теряются. Воспроизводится самим аддоном: сет из `convert_tile_to_set` содержит только DO+ERM+Normal. Нужен fallback: распаковка каналов из ERM. |
| 3 | `operators_atlas.py:744` | **Create Atlas Only (HIGH) даёт чёрный атлас для DO-only сетов** — диффуз собирается только из `T_*_Diffuse.png` без DO-first ветки (которая есть у Create Atlas from Object); `create_atlas_for_type` всегда возвращает картинку, чёрный результат пишется с сообщением «Атлас создан». |
| 4 | `operators_bake.py:506` | **Selected-to-active тихо портит общие материалы.** `bake_metallic_via_roughness` / `bake_emit_via_roughness` не дедуплицируют материалы: при общем материале на двух highpoly второй снапшот фиксирует уже искажённое состояние и при откате перетирает корректный — Metallic=0.0 навсегда, линки перепутаны. Фикс — `processed_materials`-сет (как в `disable_metallic_for_diffuse`, стр. 366). |
| 5 | `operators_frame.py:123` | **Frame с оверлеем рассинхронизирует альфу с диффузом**: overlay-извлечённая `Frame_Opacity` затирается обычной фреймовой версией без оверлея (исходный Opacity обрабатывается позже DiffuseOpacity в цикле). |

### 3.2 Средние (подтверждены)

**Атласы:**
- Смешанная альфа: сеты без `T_*_Opacity.png` становятся полностью прозрачными (регион Opacity-атласа чёрный → `putalpha(0)`). Фикс: заливать отсутствующую Opacity белым. (`operators_atlas.py:756`)
- UV-ремап не идемпотентен (повторный запуск сжимает UV дважды) и ломает тайлящиеся UV > 1 — типично для фасадов. (`operators_atlas.py:2302`)
- Unpack: фейсы вне регионов раскладки сохраняют битый `material_index` и атласные UV, молча. (`operators_atlas.py:3185`)
- Apply Atlas создаёт материал `M_A_*` вне конвенции `M_Address_Type_Index` и зависит от абсолютных путей в `atlas_mapping.json` — при переносе проекта тихая потеря текстур. (`operators_atlas.py:2764`)

**Бейк / UDIM:**
- `scene.render.bake.*` (margin, cage, пассы) не восстанавливается после бейка — пользовательские настройки Bake-панели затираются навсегда; `compression=15` тоже. (`core/baking.py:163`)
- Сет из `convert_tile_to_set` без альфы нельзя подключить ни одним connect-оператором («мёртвый» сет). Фикс: всегда именовать Diffuse как DiffuseOpacity (HIGH-режим переживает RGB без альфы). (`operators_udim.py:1676`)
- Revert UDIM: полигоны в отрицательной UV-зоне получают тайл 1000 и паразитный сдвиг (−9, +1) — координаты разрушаются. (`operators_udim.py:1445`)
- `trace_to_texture_node` не заходит внутрь node groups и игнорирует muted-линки — smart resolution деградирует до пользовательского разрешения. (`core/baking.py:347`)

**Сеты / файлы:**
- `CreateFrameOnFiles` пишет PNG-байты в файлы `.jpg/.tga/.bmp/.tiff` (filter_glob разрешает, save всегда 'PNG'). (`operators_frame.py:474`)
- Frame не исключает атласы (в отличие от mirror) и оставляет пустые папки `S_*_Frame`. (`operators_frame.py:117`)
- Resize принудительно квадратизирует неквадратные текстуры и молча апскейлит (256 → 4096 без предупреждения). (`operators_sets.py:108`)

**Share / инфраструктура:**
- Гонка read-modify-write индекса `agr_clipboard.json`: два человека затирают записи друг друга; транзиентная ошибка листинга при refresh может стереть весь индекс. (`operators_share.py`)
- Пользовательские оверлеи копируются в `resources/` аддона — при установке через junction попадают в git working tree и в `make_zip.py`-дистрибутив. (`operators_frame.py:18`)

### 3.3 Опровергнуто (не тратить время)

- Рассинхрон ключей rename и потеря ERM-детекции — **уже исправлены** в рабочей копии (актуальны только для закоммиченного HEAD).
- «UDIM-тайлы не регистрируются без `image.tiles.new`» — опровергнуто эмпирическим тестом в Blender 5.0.1: автодетект при `source='TILED'` работает, `reload()` подхватывает новые тайлы.
- Утечка файловых хендлов в frame — CPython refcounting закрывает хендл при выходе из execute; лишь гигиена кода (перейти на `with`).
- IHDR-детекция альфы (tRNS / белая альфа) — не дефект: ни один путь записи аддона не создаёт такие PNG, семантика флага соответствует документации.

### 3.4 Мелочи (low, по желанию)

- Мёртвый код: `get_atlas_naming`, `determine_alpha_resolution`, `check_normal_is_only_normal_map`, недостижимые fallback'и в атласе.
- Пять копий побайтового парсера PNG IHDR — свести к одной `read_png_ihdr(path)`.
- `blend_method = 'HASHED'` устарел с Blender 4.2 — проверить в 5.x, обернуть в `hasattr`.
- `PILLOW_AVAILABLE` кэшируется при импорте — после установки Pillow предупреждение висит до перезапуска.
- Дублирующиеся слоты одного материала пакуются в атлас дважды; `generate_procedural_atlas_name` сканирует не ту папку.
- Easteregg: при несбалансированном reload оригинальный draw меню теряется.
- refresh сбрасывает выделение сетов после каждой пакетной операции.
- `bl_options {'UNDO'}` на файловых операциях вводит в заблуждение — Ctrl+Z файлы не вернёт.
- ~350–400 строк копипасты между CreateAtlasOnly / CreateAtlasFromObject (6 дословно скопированных методов) — источник бага №3.
- ~800 строк дублированной rename-логики между `operators_rename.py` и `operators_rename_project.py` — первопричина всех расхождений.

## 5. Рекомендуемый порядок действий

1. **Дописать ветку `'do'` в `reconnect_textures`** (`operators_rename.py`) — единственная реальная незавершённость текущего диффа, теряет текстуры.
2. **Закоммитить рабочую копию** осмысленными коммитами — фикс потери текстур сейчас существует только на диске.
3. **Точечные фиксы атласов и бейка:** ERM-fallback (№2), DO-first в Create Atlas Only (№3), дедупликация материалов в бейке (№4), белая заливка отсутствующей Opacity, фикс порядка обработки в frame (№5).
4. **`poll_message_set`** — час работы, навсегда снимает вопрос «почему кнопка отключена».
5. **AGR Validate** как каркас, на который лягут FBX-экспорт и сборщик пакета сдачи.
